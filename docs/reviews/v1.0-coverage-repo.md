# v1.0 coverage review: repository against the deployment guide

Reviewer X, 2026-11-15, read-only. Rule audited: CLAUDE.md "The guide is self-contained". Every
reader-relevant item in `stack/*/README.md`, the comments of every file under `stack/`, `clients/`,
`deploy/` and `evals/`, `clients/README.md`, `evals/README.md`, and the docstrings, usage text and
`--help` output of `tools/*.py`, `tools/*.sh` and `tools/hooks/pre-push` (all subcommand helps run)
was checked against `guide/chapters/*.md` in the order of `guide/guide.yaml`. An item counts as
covered only when a chapter tells the reader what to do with it; an `{{ include }}` alone does not.
Appendix E (`guide/chapters/e-config-files.md`) was checked for every repository file that the
reader installs, copies, builds or edits.

Result: 1 blocker, 3 major, 17 minor.

## Notes outside the coverage question

- `stack/web/README.md:235-236` says no workflow publishes the MCP hub image yet;
  `.github/workflows/mcp-hub-image.yml` exists and `stack/web/compose.yaml:169` says it publishes
  from `main`. The README is stale; the guide follows the compose file.
- `clients/install.sh:74-76` writes `client.env` under `$XDG_CONFIG_HOME` when that is set, while
  the profile block (`install.sh:345`), `claude-local`, `smoke.py` and `eval.py` read
  `~/.config/local-agent-stack/client.env`. With a non-default `XDG_CONFIG_HOME` the two differ.
- Ch. 4 states that keys never appear on a command line, but Ch. 6 ("Check the Open WebUI
  connections and document settings", steps 6 and 7) and Ch. 10 ("Monitor the gateway") expand a
  key into the arguments of `docker exec ... curl -H "Authorization: Bearer $K"`, where the process
  list shows it. The `printf ... | curl -H @-` form of Ch. 4 avoids that.
